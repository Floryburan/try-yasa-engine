# LLM-check 目录说明

本文按 2026-11-10 的目录和代码整理。根目录文件逐个说明；实验中大量按函数 ID、调用位置 ID、请求 ID 重复生成的文件，按目录和命名规则说明。

`LLM-check` 负责提取上下文、调用模型、保存判断、评测和向 YASA 导入结果。真正的符号解释和污点传播在上一级 `src/` 引擎中进行。

## 1. 先看当前主要流程

```text
仓库源码 + YASA UAST 全局索引
    ├─ jev_scan.py          → 逐函数识别 entrypoint
    ├─ jev_sources.py       → 围绕已识别入口判断 source
    └─ jev_sinks.py         → 逐调用位置判断 sink 及危险参数
              ↓
    link_sink_candidates.py → 从 sink 沿调用图反查入口，关联 source
              ↓
    export_yasa_inputs.py   → 导出入口、source、sink 及参数
              ↓
    YASA 引擎               → 从入口正向传播，在导入的 sink 参数处检查污点
              ↓
    summarize_yasa_taint.py → 汇总 SARIF、传播关系和运行统计
```

以上三种模型判断是不同任务。反查得到的是候选调用关系，之后才由 YASA 检查传播。

当前启用 `--llmInputFile` 时要求 `yasa-llm-input/v2`：入口、source、sink 及危险参数都使用导入结果，原有 Python 入口/source/sink 识别规则不参与补选。模型没选危险参数的 sink 会保留记录，但不会自动改为检查所有参数。

输入位置匹配、数据传播和漏洞确认是不同事情。报告中的传播告警，不等于已经证明可以绕过过滤或权限检查。

## 2. 根目录文件

### 2.1 主流程脚本

| 文件 | 作用 |
|---|---|
| [jev_scan.py](jev_scan.py) | 全仓库逐函数入口扫描的主入口，准备精简上下文、调用 Jev、保存结果和打印统计。 |
| [jev_sources.py](jev_sources.py) | source 任务的命令入口；支持小样输入复用以及全部模型入口的 source 扫描。 |
| [jev_source_scan.py](jev_source_scan.py) | `jev_sources.py` 使用的批量准备和执行逻辑，处理候选分批、并发 API 调用、保存结果及续跑。 |
| [jev_sinks.py](jev_sinks.py) | 枚举 Python 调用位置，让 Jev 判断是否为潜在 sink、属于什么类别、哪些实参危险，并保留置信度。 |
| [link_sink_candidates.py](link_sink_candidates.py) | 离线读取 sink、入口、source 和 YASA 调用图；定位 sink 所在函数，反查调用者，输出候选关联和缺失信息。它不证明参数数据流。 |
| [export_yasa_inputs.py](export_yasa_inputs.py) | 把已保存的 Jev 判断导出成 YASA v2 输入；可按已有反查目录选择 sink 和候选入口，不重新调用模型。 |
| [summarize_yasa_taint.py](summarize_yasa_taint.py) | 读取引擎日志、导入诊断和 SARIF，生成状态、总结和 source→sink CSV；`--watch` 可等待扫描并持续更新状态。 |

### 2.2 上下文和目标身份

| 文件 | 作用 |
|---|---|
| [context_graph.py](context_graph.py) | 读取 UAST 全局索引，解析作用域、导入和名称，整理函数间静态关系及上下文。不是完整运行时调用图或数据依赖图。 |
| [compact_context.py](compact_context.py) | 构造入口判断的精简上下文：保留目标函数，补直接使用位置和必要的外围代码，控制重复及长度。 |
| [binding_context.py](binding_context.py) | 补充方法所属类、实例、继承接收者和绑定位置等证据，不直接据此给出入口标签。 |
| [function_identity.py](function_identity.py) | 建立源码函数定义的稳定身份，合并同一物理定义的别名，避免同一函数被重复选中。 |
| [source_context.py](source_context.py) | 根据入口的形成方式组合取证范围，提取未标注的 source 候选，构造模型输入。多种形成方式的证据会合并。 |
| [sink_context.py](sink_context.py) | 为调用位置构造上下文和实参清单，记录位置参数、关键字参数、接收者，以及必要的赋值和辅助函数证据。不是完整反向切片。 |
| [yasa_callgraph_context.py](yasa_callgraph_context.py) | 按源码位置把目标函数匹配到已导出的 YASA 调用图，并生成有范围限制的调用图视图。 |
| [input_length_audit.py](input_length_audit.py) | 汇总模型输入长度、服务返回的 token 用量及截断信息；区分“没有报告是否截断”和“明确没有截断”。 |

### 2.3 API、配置和统计

| 文件 | 作用 |
|---|---|
| [jev_config.py](jev_config.py) | 读取 `.env` 和环境变量中的 Jev 配置，构造服务地址及请求头，供 Jev 相关脚本复用。 |

| [config.example.json](config.example.json) | 通用 Chat Completions 客户端的配置样例；不能直接当作 Jev `.env` 配置使用。 |
| `.env` | 本地 Jev 配置。当前读取的键为 `TYPESAFE_API_KEY`、`TYPESAFE_BASE_URL`、`TYPESAFE_DEFAULT_MODEL`。包含密钥，不应提交到仓库。 |
| [.gitignore](.gitignore) | 本目录的忽略规则，包括 `.env`、`runs/`、`__pycache__/` 和本地 `config.json`。 |

### 2.4 参考标注、评测和报告提取

| 文件 | 作用 |

| [build_ctfd_reference.py](build_ctfd_reference.py) | 根据 CTFd 源码、绑定和框架契约建立入口静态参考标注，不读取模型预测来定标签。 |

### 3.6 `__pycache__/`：Python 自动缓存
